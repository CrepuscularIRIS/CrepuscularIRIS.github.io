两个 DeepMind 系统——Aletheia 和 AlphaEvolve——标志着 AI 处理数学推理的方式发生了结构性转变。它们不是增量改进。背后的设计决策对于任何需要产生**可验证正确**输出的系统构建者都具有启发意义。

## 核心问题：推理幻觉

语言模型会产生幻觉。在创意写作中，幻觉是风格；在代码生成中，测试能捕获它们；在数学中，幻觉是致命的：一条看起来合理但包含细微错误的证明，比没有证明更糟，因为它可以通过引用传播，扭曲整个子领域的认知。

朴素修复方案——在数学输出上做 RLHF——无法扩展到新数学。你可以通过标注足够多的本科习题来训练模型写出正确的微积分。但你无法通过标注来训练它证明新猜想，因为标注根本不存在。

DeepMind 在 Aletheia 上的洞察是架构层面的，而非训练层面的：**将候选解的生成与其验证分离**，确保 LLM 的不可靠性不会传播到已发表结果中。

## Aletheia：生成器-验证器架构

Aletheia 使用基于 Gemini 构建的多智能体架构，包含用于生成、验证和修正的独立组件：

**生成器**：一个基于 Gemini 的智能体生成候选数学论证——探索证明策略，提出构造，方法失败时回退。生成器以高探索广度运行，产生大量候选，而非试图一次做对。

**验证器**：一个独立组件评估生成器的候选是否正确。公开材料中未完全详述具体的验证机制，但该架构同时支持形式化检查（通过 Lean 4 或 Isabelle 等证明助手）和结构化数学审查。关键设计选择在于：验证器独立于生成器——它不能被生成器的推理"说服"，只能被结果的正确性说服。

**修正器**：当验证器发现问题，修正智能体尝试修复它们——创建一个生成-验证-修正循环，迭代收敛至正确解。

人类看到的自然语言解释来自已验证的结果——而非来自探索过程。模型写出它证明的内容，而非它尝试过的内容。

```
问题陈述
      │
      ▼
┌─────────────────────┐
│   生成器 (LLM)       │  ← 探索证明策略
│   候选搜索           │  ← 内部推理，不对外暴露
│   高广度             │  ← 大量候选，允许低精度
└─────────┬───────────┘
          │ 候选数学论证
          ▼
┌─────────────────────┐
│   验证器            │  ← 独立于生成器
│   正确性检查         │  ← 形式化或结构化审查
│   不接受"说服"      │  ← 二元判断：正确或错误
└─────────┬───────────┘
          │         │
          │ FAIL   │ PASS
          ▼         ▼
┌──────────┐  ┌──────────────────┐
│ 修正器   │  │ 解释器 (LLM)      │
│ 修复并   │  │ 人类可读的         │
│ 重试     │  │ 书面说明           │
└──────────┘  └──────────────────┘
```

这一架构消除了一种特定的失败模式：自信但错误的模型。生成器可以在搜索中保持不确定、探索性、甚至混乱——只要验证器在错误传播前捕获它们，这一切都不重要。生成-验证-修正循环意味着即使初始尝试有缺陷，也能通过迭代收敛到正确结果。

## 求解开放问题：正确校准声明

Aletheia 产生了开放数学问题解的声明，这一说法需要仔细解读。DeepMind 报告称，在 200 个候选解中，大约 6.5% 是"有意义的正确"——这个命中率很低，正是生成器-验证器架构明确设计来处理的。系统生成大量候选，知道大多数会失败；验证器过滤出可行的那些。

所解决的问题似乎集中在组合学和图论——这些领域大量问题仍处于开放状态，因为证明需要难以发现但一旦找到就相对容易验证的复杂论证。有数学家指出，虽然被解决的问题在技术上已开放数十年，但并非该领域最深或最难抵抗的猜想。

这种校准很重要。意义不在于 AI 解决了数学中最难的开放问题——它没有。意义在于生成器-验证器架构能在正确性不可妥协的领域中产生**一些**真正新颖、可验证正确的结果。如果验证成本低廉且生成可并行化，6.5% 的命中率就足够好了。

## AlphaEvolve：改进 Ramsey 界

AlphaEvolve 是一个独立但互补的系统，于 2025 年 5 月首次亮相，2026 年初发表了新结果。Aletheia 推理证明，而 AlphaEvolve **发现更好的构造和算法**——其最引人注目的最新成果是改进了多个 Ramsey 数的已知下界。

Ramsey 理论问的是：一个图必须有多大，才能保证它要么包含一个大小为 j 的完全子图，要么包含一个大小为 k 的独立集？AlphaEvolve 通过寻找更大的完全图 2-染色方案（避免禁止的单色子图），改进了多个非对称 Ramsey 数（包括 R(3,13)、R(3,18)、R(4,13) 等）的下界。

演化循环的工作方式如下：

1. 从当前最佳构造开始（一个图染色、一个算法、一个数学函数）
2. Gemini 2.5 Pro 生成变异：在保留所需性质的同时，可能扩展到更大实例的替代构造
3. 每个变异都根据形式化标准进行评估（这个图染色是否避免了单色 K₅？）
4. 表现最好的变异存活下来，成为下一代的父代
5. 重复数百或数千代

```python
# AlphaEvolve Ramsey 下界演化的概念代码
def evolve_ramsey_construction(
    initial_coloring: np.ndarray,  # 带 2-染色的邻接矩阵
    target_k: int = 5,
    generations: int = 500,
) -> tuple[np.ndarray, int]:
    """演化图染色以寻找更大的 R(k,k) 下界。"""
    current_best = initial_coloring
    current_size = initial_coloring.shape[0]

    for gen in range(generations):
        # Gemini 生成候选扩展/修改
        # 关键洞察：变异是语义驱动的，而非随机位翻转
        # LLM 理解图结构，可以提出
        # 保留无单色团性质的扩展方案
        candidates = generate_mutations(current_best, n=20)

        for candidate in candidates:
            n = candidate.shape[0]
            if n > current_size and has_no_monochromatic_clique(candidate, target_k):
                current_best = candidate
                current_size = n
                print(f"Gen {gen}: new lower bound R({target_k},{target_k}) >= {n+1}")

    return current_best, current_size
```

使 AlphaEvolve 的变异算子从根本上区别于传统演化搜索的是语义理解。经典方法通过翻转随机边来变异图染色——在指数级大的空间中进行的盲目搜索。Gemini 可以生成**结构信息驱动**的变异：它识别当前染色中的模式（对称群、块结构、边密度分布），并提出可能保留无单色团性质的扩展方案。这是随机变异与有信息探索之间的区别。

Ramsey 结果的意义不在于特定界的改进有实际用途，而在于它们证明了 LLM 引导的搜索可以找到补充数十年人类努力和经典计算机搜索的数学构造。Ramsey 染色的搜索空间超指数增长——n 个顶点有 2^(n choose 2) 种可能的染色方案——而语义变异提供了一种比随机搜索更高效地穿越这个空间的方式。

## 连接线索：形式结构作为安全网

两个系统共享一个设计原则：**在将 LLM 输出接受为 ground truth 之前，使用形式化或经验验证来过滤它们**。

Aletheia 通过其独立验证器组件做到这一点。AlphaEvolve 通过组合性质验证（构造是否满足所需性质？）和基准评估做到这一点。在两种情况下，LLM 负责探索和生成，但它不能宣布成功——只有独立的、客观的评估步骤可以做到这一点。

这是一个可推广到数学之外任何满足三个条件的领域的模式：

1. **正确性可以被形式化或经验验证**（即使验证成本高昂）
2. **有效解的空间太大，无法穷举搜索**（因此需要智能探索）
3. **专家人工评估成本高或速度慢**（因此自动化价值高）

| 领域 | 生成器 | 验证器 | 验证成本 |
|------|--------|--------|---------|
| 定理证明 | LLM 证明搜索 | 形式化证明检查器 | 毫秒级 |
| 算法发现 | LLM 代码变异 | 基准测试套件 | 秒到分钟 |
| 药物发现 | LLM 分子生成 | 分子动力学模拟 | 小时级 |
| 编译器优化 | LLM pass 生成 | 测试套件 + 性能基准 | 分钟级 |
| 电路设计 | LLM 原理图生成 | SPICE 模拟 | 分钟到小时 |
| 蛋白质工程 | LLM 序列设计 | AlphaFold 结构预测 | 分钟级 |

约束条件始终是验证器。在数学中，形式化证明系统以接近零的成本提供了近乎完美的验证器。在药物发现中，分子模拟成本高昂且是近似的。生成器-验证器模式的经济性取决于你的验证器有多便宜和可靠。

## 实践中构建生成器-验证器系统

对于想在纯数学之外应用这一模式的团队，该架构可以经过调整后迁移：

**第 1 步：刻画你的验证函数。** 在你的领域中，"正确"意味着什么？你能以多低的成本检查它？如果验证成本高昂（运行完整模拟、部署到预发环境），你需要多阶段验证管道：先用廉价过滤器（语法检查、类型检查、启发式边界），昂贵的检查只用于通过廉价过滤器的候选。

**第 2 步：最大化生成器多样性。** 生成器的工作是探索，不是精确。使用高温度、多种采样策略和多样化的提示框架来产生广泛的候选。一个生成 1000 个候选、5% 有效率的生成器，比一个生成 10 个候选、50% 有效率的生成器更有用——只要验证成本低廉。

**第 3 步：分离生成器和解释器。** 探索证明策略（或生成候选分子，或提出代码变异）的模型，不应该和向人类解释结果的模型是同一个。生成器针对搜索空间的覆盖率进行优化。解释器针对沟通的清晰度和准确性进行优化。不同的目标，不同的训练信号，往往是不同的模型。

```python
# 生成器-验证器管道模板
from dataclasses import dataclass
from typing import Generic, TypeVar

T = TypeVar('T')  # 候选类型

@dataclass(frozen=True)
class VerificationResult(Generic[T]):
    candidate: T
    is_valid: bool
    score: float  # 二元有效性之外的质量指标
    verification_trace: str  # 审计轨迹

def generator_verifier_pipeline(
    problem: str,
    generate_fn,      # 基于 LLM 的候选生成器
    verify_fn,        # 确定性/经验验证器
    explain_fn,       # 基于 LLM 的结果解释器
    n_candidates: int = 100,
    top_k: int = 5,
) -> list[str]:
    # 生成多样化候选
    candidates = generate_fn(problem, n=n_candidates)

    # 验证所有候选（可并行）
    results = [verify_fn(c) for c in candidates]

    # 过滤有效、按质量排序
    valid = sorted(
        [r for r in results if r.is_valid],
        key=lambda r: r.score,
        reverse=True,
    )[:top_k]

    # 解释最优结果（与生成器使用不同的模型/提示）
    explanations = [explain_fn(r.candidate, r.verification_trace) for r in valid]

    return explanations
```

## 这对 AI 在研究中的意义

Aletheia 的意义不在于它解决了一些 Erdős 问题。意义在于它展示了一种可行的架构，使 AI 系统能够产生**可信赖的**新颖贡献——不是因为模型可靠，而是因为验证层使不可靠性变得无关紧要。

对于 AI 相邻领域的研究者：问题不再是 LLM 能否辅助形式化工作。问题是你的验证管道是否足够好，能充分利用它们。如果你的领域有强验证器，你可以将 LLM 视为极其强大但不可靠的假设生成器，让验证器负责质量控制。

AlphaEvolve 指向了一个相关但不同的能力：AI 作为算法工程师。不是发现证明，而是发现**更好的实现和构造**——更好的 RL 更新规则、更好的数值方法、更好的组合构造、更好的矩阵分解。这些是立即可用的改进，不需要理论突破，只需要更高效地搜索可能性空间。

Ramsey 数结果和开放问题解是概念验证。真正的冲击来自于当这个架构被应用到那些验证器足够便宜、搜索空间足够昂贵的领域，使经济账能够成立。数学恰好是验证最便宜、最可靠的领域，这就是 DeepMind 从这里起步的原因。

对其他领域的问题：你能否构建一个足够可靠的验证器，将不可靠的 LLM 探索转化为可信赖的大规模结果？生成器-验证器模式是 AI 辅助科学的架构模板——但它在每个领域的适用性完全取决于你能构建的验证函数的质量。
