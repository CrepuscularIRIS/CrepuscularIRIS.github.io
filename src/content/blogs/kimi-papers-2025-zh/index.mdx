长上下文注意力的核心问题很清晰：标准自注意力的计算复杂度随序列长度呈 O(n²) 增长，因此 200K token 的上下文窗口大约比 10K token 窗口贵 400 倍。所有通向长上下文 LLM 的方案都必须解决这个成本问题，设计空间分裂为两条路线——要么近似完整的注意力矩阵（线性注意力、滑动窗口、核化注意力），要么从中稀疏地选取一部分（块稀疏、top-k、路由选择）。

Moonshot AI 的 MoBA（Block Attention 混合专家，Mixture of Block Attention）是第二条路线在生产环境中落地的最典型案例。2025 年 2 月发布，部署于 Kimi 生产栈的 200K token 上下文，基于 Apache 2.0 开源——这是少数从论文到生产部署仅用几个月的注意力机制之一。

核心思想简洁到一段话就能说清：将 KV Cache 划分为固定大小的块（通常每块 512–4096 tokens），对每个查询 token 与每个块计算相关性分数（使用查询向量与该块均值键向量的点积），为每个查询选取 top-k 最相关的块，然后仅在这些被选中的块上计算注意力。**无学习路由参数，无辅助损失函数，无需特殊训练流程。**

## MoE 类比及其成立原因

MoBA 的名字——Block Attention 混合专家——借鉴自 Mixture of Experts，这个类比是精确的。在标准 MoE 层中，路由器负责选择由哪个专家网络处理每个 token。在 MoBA 中，"路由器"是查询-键的点积，"专家"是 KV 块。这一并行性还可以进一步延伸：

| MoE 组件 | MoBA 对应 |
|---|---|
| 专家网络 | KV 块（一段连续的键值序列） |
| 路由器 | 查询-块点积分数 |
| Top-k 选择 | 每个查询 token 选取 top-k 个块 |
| 负载均衡损失 | 无需（块是固定的，非学习的） |

最后一行是关键差异。标准 MoE 需要精细的负载均衡来防止路由器崩溃——即路由器倾向将所有 token 发送给少数专家、导致其他专家闲置的问题。MoBA 不存在这个问题，因为"专家"（KV 块）不是学习参数，它们是输入序列的固定分区——**没有什么可以"崩溃"的**。

这意味着 MoBA 可以零架构改动地插入现有模型。注意力计算方式被修改了，但模型权重完全相同。用全注意力训练（保证质量），在推理时切换到 MoBA（换取速度）。同一份 checkpoint 服务两种模式。

```python
# 简化的 MoBA 前向传播
def moba_attention(
    query: Tensor,       # [batch, heads, seq_len, dim]
    key: Tensor,         # [batch, heads, seq_len, dim]
    value: Tensor,       # [batch, heads, seq_len, dim]
    block_size: int = 2048,
    top_k: int = 3,
) -> Tensor:
    num_blocks = key.shape[2] // block_size

    # 计算块级相关性分数
    # 在每个块内对键做均值池化
    key_blocks = key.reshape(*key.shape[:2], num_blocks, block_size, -1)
    block_keys = key_blocks.mean(dim=3)  # [batch, heads, num_blocks, dim]

    # 每个查询对每个块打分
    scores = torch.einsum("bhsd,bhnd->bhsn", query, block_keys)

    # 为每个查询 token 选取 top-k 个块
    _, top_indices = scores.topk(top_k, dim=-1)  # [batch, heads, seq_len, top_k]

    # 收集被选中的 KV 块并计算注意力
    # (实际实现使用高效 gather + flash attention)
    selected_k = gather_blocks(key, top_indices, block_size)
    selected_v = gather_blocks(value, top_indices, block_size)

    return flash_attention(query, selected_k, selected_v)
```

实现细节值得关注。朴素方案——收集选中块、拼接、运行标准注意力——内存访问模式很差。MoBA 的生产实现使用自定义 CUDA 内核，将块选取与注意力计算融合，避免了中间张量的物化。

## 性能数字及其语境

MoBA 的 headline 数据是：序列长度 32K、块大小 2048、top-k=3 时实现 **40 倍加速**。这超过了理论稀疏比（约 5 倍，因为只注意力到 3/16 的块），因为融合 CUDA 内核同时消除了物化完整注意力矩阵的内存带宽开销——加速来自 FLOPs 减少和内存访问模式改善的共同作用。但 headline 数据掩盖了参数之间的关系：

| 序列长度 | 块大小 | Top-k | 加速比 | 质量损失（困惑度 delta） |
|---|---|---|---|---|
| 32K | 2048 | 3 | 40x | 可忽略（&lt;0.1%） |
| 128K | 2048 | 8 | ~15x | 可忽略 |
| 200K | 4096 | 12 | ~8x | 在大海捞针测试上可测量 |

加速比随序列变长而降低，因为更长序列需要选取更多块（更高的 top-k）来维持质量。在 200K tokens、4096-token 块下，有约 50 个块，选取其中 12 个意味着仅注意力到约 24% 的序列——相比全注意力仍有大幅削减，但在短序列上可实现的极端稀疏程度已不可同日而语。

质量-速度的权衡完全由 top-k 控制。k 值越低推理越快，但遗漏相关上下文的风险越高；k 值越高质量越好，但加速比下降。生产环境中，Moonshot AI 使用自适应 top-k——前几层用更高的 k（全局注意力模式最为关键），后几层用更低的 k（注意力倾向更局部）。

## MoBA 做对了而其他方案没做到的事

### 无训练成本

大多数稀疏注意力机制需要用稀疏模式训练模型，因为模型必须学会"绕过"缺失的注意力连接。MoBA 不需要——用全注意力训练，获得最高质量，推理时切换到稀疏注意力。这是因为块选择机制（查询-键点积）使用了与全注意力相同相似度度量。模型的注意力模式已经隐式编码了哪些块是相关的；MoBA 只是把这个选择显式化并丢弃其余部分。

### 零辅助参数

基于路由的方案（如 Mixture of Depths 或学习型稀疏注意力）需要添加参数——一个必须被训练、平衡和维护的路由器网络。MoBA 添加的参数为零。相关性分数由现有的查询和键向量计算得出。这意味着 MoBA 兼容任何 Transformer 模型，无需架构变更、权重格式变更或额外训练。

### 优雅降级

当 top-k 等于总块数时，MoBA 数学上等同于全注意力（不计块均值近似带来的浮点差异）。这意味着你可以通过调整一个整数在全注意力和稀疏注意力之间插值，行为没有间断。其他稀疏注意力方法——滑动窗口、局部+全局、哈希——在"使用机制"和"不使用机制"之间有定性跃迁，可能导致意外行为。

## VMoBA：跨模态扩展

2025 年 6 月，Moonshot AI 发布了 VMoBA（Video Mixture of Block Attention，[arXiv:2506.15465](https://arxiv.org/abs/2506.15465)），将 MoBA 扩展到视频扩散模型。这一适配在架构层面颇具启发性。

视频扩散 Transformer（基于 DiT 的模型）处理展平的时空网格产生的 token 序列——每个视频帧被分块为空间 token，帧沿序列维度拼接。一段 16 帧、256×256 分辨率的视频在 16×16 块大小下产生 16×256=4096 个 token。在生成分辨率（64 帧、512×512）下，序列长度达到 65K+ tokens。

VMoBA 的关键改动在于：块沿时间轴或空间轴定义，而非按序列位置。**时间块**将相邻帧的所有空间 token 归为一组；**空间块**将跨帧相同空间区域的 token 归为一组。这使块边界与视频数据的自然相关性结构对齐——相邻帧相关性高于远距离帧，相邻空间块的相关性也更高。

VMoBA 的意义不在于视频专项结果（3–5 倍加速下与全注意力持平），而在于证明了 MoBA 的核心机制——通过查询-键相似度的参数无关 top-k 块选取——跨模态迁移无需修改选择算法。唯一改动是块的定义方式，这是数据预处理决策，而非模型架构决策。

## 对注意力架构设计空间的影响

MoBA处于设计空间中一个有趣的位置。它不是理论上最优雅的方案（线性注意力的替代品如 RetNet 或 Mamba 的选择性状态空间模型拥有更干净的渐近性质），也不是压缩最激进的（哈希类方法如 Reformer 可实现更低内存占用）。但它同时具备三个属性，共同解释了它在生产中的采纳：

1. **即插即用**：无需重训练，无需架构变更，无需调参新超参数
2. **质量可预测**：top-k 与质量的关系是单调且平滑的
3. **生产友好**：块级操作良好映射到 GPU 内存层级结构

MoBA 成功的教训在于：注意力机制的生产采纳门槛不是理论效率，而是**集成成本**。一个达到理论最优 80% 效率但训练流水线零改动的方案，必然打败达到 100% 效率但需要重训练模型的方案。

这对当前注意力机制研究浪潮有深远影响。需要在训练阶段修改的方法——结构化状态空间模型、线性注意力变体、混合架构——面临比仅修改推理路径的方法更高的采纳壁垒。最重要的模型（最大、最昂贵的前沿模型）恰恰是重训练成本最高的，这意味着推理时稀疏化如 MoBA 在部署层面具有结构性优势。

## MoBA 开启的设计空间分类学

比列举具体 2026 年变体（其中许多仍是移动靶或未公开）更有用的是绘制 MoBA 结晶出的设计轴。今天任何评估块稀疏方法的人实际上都在隐式地在这几个轴上选取位置：

**块边界**：固定序列位置块（MoBA 原始选择）vs. 内容自适应块（在 prefill 时按相似度聚类 KV 对）。固定边界更便宜、并行化更干净；内容自适应边界与输入相关性结构对齐，但需要 prefill 时聚类。

**分数函数**：均值键点积（MoBA 默认，零参数）vs. 学习型路由器（MoE 风格）vs. 哈希桶化。均值键最简单，哈希最便宜，适合连均值键评分过程都嫌重的内存受限场景。

**Top-k 策略**：全局 top-k（所有查询相同 k）vs. 阈值法（按分数大小可变 k）vs. 自适应（k 响应层深或输入长度）。全局 top-k 最简单，也是 MoBA 论文所采用的；自适应策略可以改善异构输入的质量，但使基准测试复杂化。

**稀疏训练**：推理时稀疏化（MoBA 原始定位——训练密集，部署稀疏）vs. 稀疏感知预训练（模型从一开始就以稀疏模式训练，如同"原生稀疏注意力"方向）。推理路径零训练风险，是 MoBA 快速落地生产的原因。稀疏感知路径可在训练复杂度代价下获得更好的峰值质量，而这只有垂直整合的实验室才能承担。

**块注意力混合**：逐层纯块稀疏注意力（MoBA）vs. 交替密集+块稀疏层 vs. 混合状态空间+注意力堆栈。混合方案——将线性时间状态空间机制（Mamba、S6、RWKV）与偶尔执行检索工作的注意力层混合——是 1M+ token 上下文的一个活跃研究方向。

这些轴并不正交——选择相互影响。一个学习型路由器+内容自适应块+稀疏感知预训练的系统，与一个均值键评分器+固定块+推理时稀疏化的系统，即使在基准测试中都被称为"块稀疏注意力"，也是完全不同的系统。当一篇论文报告块稀疏结果时，值得问的第一个问题是：该方法处于设计空间的哪个位置，因为这决定了权衡是什么、作者在优化哪个轴。

## MoBA 揭示的基础设施导向研究规律

更深层的教训在于注意力研究如何被筛选进入生产。在 MoBA 之前，学术出版物中占主导的注意力效率叙事是**线性注意力**：具有理论上次二次渐近复杂度的机制。问题是线性注意力需要用新机制训练模型，而没有前沿实验室愿意在赌注上吸收那个训练风险。所以线性注意力论文留在了文献中，没有到达前沿规模已部署模型。

MoBA 反其道而行。它在理论上不如线性注意力优雅（在被激活块内仍是二次的，只是一个更小的 n），但它需要零训练改动。部署故事是"换掉推理内核，保留权重"。这个故事与大规模 ML 基础设施的实际运作方式兼容：模型权重是系统中成本最高、风险最敏感的制品，任何无需触碰它们就能进行改装的东西，都对任何无法做到这一点的方案具有结构性成本优势。

因此，2026 年注意力机制的筛选压力不是"孤立最优"，而是"**在不重训练模型前提下的最优效率**"。这比 2019–2023 年注意力效率文献探索的设计空间要狭窄得多，这也解释了为什么现在获得牵引力的方法绝大多数是推理时稀疏化变体。稀疏感知预训练变体也存在，一些团队在发布，但只有同时控制训练配方和部署栈的实验室才能这样做——这个组织清单远比运行大型开源权重模型的团队短得多。

长上下文推理经济学将继续推动这个方向。前沿上下文窗口在未来 12–24 个月内有望达到 10M tokens。10M token 密集注意力的计算成本在哪个硬件代际下都是不可承受的。具有训练后部署路径的块稀疏方法是唯一能随这个经济学规模扩展的机制，无需每次有人发布新稀疏模式时就触发一次数十亿美元的重训练事件。这才是那个属性，决定了哪些注意力机制能从 arXiv 走向生产。
