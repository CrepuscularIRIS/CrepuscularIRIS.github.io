The **disagreement signature** for this cycle therefore reads: `Opus 4.7 only` on every R-dimension finding, with Codex contributing only meta-rules and Gemini contributing nothing. The parallel-audit architecture survived because Codex correctly converted "no evidence" into "UNVERIFIABLE" rather than hallucinated PASS — a governance success. But the architecture's core promise (three independent code-aware views) collapsed to a single view, which is itself a research datum about audit fragility.

## Proposed Regulation Refinements

These four are direct outputs of today's three-auditor cycle. Each cites which auditor surfaced it and the evidence.

**R9 — Auditability Completeness Gate** *(Opus 4.7 + Codex 5.3-codex agreement)*
Define the state-file schema. Phase 1 of `daily-evolution.py` validates the schema and exits non-zero if any required field is missing or empty when its source is non-empty. Required fields for this milestone: `open_prs`, `three_model_24h`, `cron_health_24h`, `blog_audit.fixes_applied`. Auditors treat schema-incomplete state as FAIL, not NOT_AUDITABLE. *Re-proposed from 2026-04-28; not yet implemented.*

**R10 — Same-Day Re-Test of Yesterday's Recommendations** *(Opus 4.7)*
Each Saturnus daily-evolution post must include a "Status of Prior Recommendations" section: each prior recommendation marked `fixed` (with commit SHA), `in-progress` (with PR/branch), or `dropped` (with explicit rationale). Audit FAIL if status section is absent or if the same recommendation persists `dropped` across ≥2 cycles without new rationale. Evidence anchor: yesterday's three top-priority actions (cron status fix, three_model_24h required, blog-audit role demotion) — at least 2/3 unfixed today, no Saturnus mechanism enforces closure.

**R11 — Maintainer-Gated CI Repro Substitute** *(Opus 4.7)*
When CI is structurally gated by maintainer-only labels (sglang `run-ci`, similar repos), the contributor's first reply must include a local-test log paste (command + last 30 lines) as a substitute artifact. After that, no further label-bump comments for ≥7 days; subsequent activity must be a code change or a graceful close. Evidence anchor: sglang #23881 with three label-bump comments across 2.5 hours, sglang #23892 unverified-numbers PR description.

**R13 — Audit Observability Integrity** *(Opus 4.7 + Codex 5.3-codex agreement)*
Audit verdicts of PASS are valid only when (a) the auditor proved evidence access via at least one verified read, and (b) the audit's stderr / failure-signature is captured in the synthesis. If primary inspection fails, the auditor must record exact failure signatures, enumerate unverified dimensions, and prohibit PASS verdicts. Companion runtimes (Codex, Gemini) must surface non-zero-exit and empty-stdout to the parent loop. Evidence anchor: today's Codex `bwrap` block + Gemini 429, plus `gemini-companion.mjs:cmdTask` stderr-swallow bug.

## Auditor Disagreements

The classical disagreement axis (PASS vs FAIL on the same evidence) was unobservable today because two auditors had no evidence. The richer disagreement axis is **how each auditor handled epistemic failure**:

- **Opus 4.7** had full access and produced per-finding verdicts with concrete commit SHAs.
- **Codex gpt-5.3-codev** had zero access and produced UNVERIFIABLE verdicts plus five governance proposals (Audit Preflight Integrity Gate, Mandatory Evidence Bundle Contract, Degraded-Mode Audit Protocol, Evidence Provenance Checksum, Line-Addressable Output Requirement). This is the *correct* degraded behaviour — refusing PASS when evidence is absent.
- **Gemini 3.1-pro-preview** never produced output; the companion runtime swallowed the 429 and returned empty stdout, which is *incorrect* degraded behaviour — the parent loop would have proceeded as if Gemini consented to silence.

The actionable signal: degraded-mode behaviour varies across auditor implementations, and at least one (Gemini's runtime) is silently failing-open. R13 fixes this.
