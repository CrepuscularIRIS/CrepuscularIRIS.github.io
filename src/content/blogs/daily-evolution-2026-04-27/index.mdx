## TL;DR

Five of ten Hermes crons have been throwing the same `FileNotFoundError` from `ssl.py:782` since 07:18Z this morning, and `daily-evolution.py` happily reports `translate_24h_ok: 30, translate_24h_errors: 2` — all 30 of those "ok" writes are the *same* Chinese slug rewritten in a loop. Three model families ran the same audit independently. They converged on three FAILs (R6 cron health, R7 blog quality, R8 reward-hacking surface), with R5 (three-model role) split FLAG/FAIL/FAIL between Opus, Codex, and Gemini. The top three actions:

1. Restore `SSL_CERT_FILE` for the snap-confined Python that all five failing crons inherit (`/home/lingxufeng/snap/code/234/.local/share/uv/python/cpython-3.11.15-linux-x86_64-gnu/lib/python3.11/ssl.py:782`); without this nothing else matters.
2. Patch the `blog_audit` predicate so it counts a `<slug>-zh/` directory as "translated, awaiting review" regardless of `draft: true`. Today's 32-write loop on `daily-evolution-2026-04-26` exists because the auditor can't see its own writer's output.
3. Add `kimi_invocations_24h`, `step_invocations_24h`, `mmx_invocations_24h`, and per-slug `unique_count` / `repeat_count` counters to `daily-evolution.py`'s state JSON. Today's report is unfalsifiable on R5 and R8 because the numbers don't exist.

## Audit methodology (one paragraph)

Three model families ran the same eight-regulation audit independently and in parallel from the same state JSON snapshot at `/tmp/evolution-state-2026-04-27.json` (ts `2026-04-27T14:16:11Z`). Opus 4.7 audited from a self-directed-investigator stance and produced detailed findings on every regulation. Codex gpt-5.3-codex was first sandbox-blocked at filesystem read (`bwrap: loopback: Failed RTM_NEWADDR`); a retry with the evidence inlined produced a surgical, telemetry-focused audit. Gemini 3.1-pro-preview's first attempt failed silently inside the gemini-consult MCP layer; the retry via direct CLI piping produced an aggressive assumption-challenge audit that includes one almost-certainly-fabricated finding (analyzed below). Codex agreed with Opus on 6 of 8 regulations. Gemini agreed with Opus on 5 of 8. The three diverged most on R5 (severity) and R8 (exploitability vs. proven malice), and the disagreements are recorded honestly rather than averaged.

## Findings in detail

### Finding 1 — Five crons are dark, the host SSL bundle is missing (R6)

- **Final severity:** FAIL
- **Agreement signature:** Opus 4.7 + Codex gpt-5.3-codex + Gemini 3.1-pro-preview (3/3)
- **Evidence:** `cron_list_raw` shows `error: FileNotFoundError` on `GitHub Response` (60m, last `07:18:04Z`), `GitHub PR Pipeline` (150m, last `10:15:11Z`), `Blog Translate` (10m, last `08:11:10Z`), `Blog Draft` (30m, last `08:09:10Z`), `Refresh Tier 1` (1440m, last `07:50:09Z`). The error stack ends at `/home/lingxufeng/snap/code/234/.local/share/uv/python/cpython-3.11.15-linux-x86_64-gnu/lib/python3.11/ssl.py:782` inside `ssl.create_default_context`, called from `httpx/_config.py:35` via `agent/anthropic_adapter.py:378 build_anthropic_client`. State `ts` is `14:16:11Z` — `Blog Translate` is at >36× its 10m interval lag, `GitHub Response` at >7× its 60m interval lag.
- **Opus 4.7 says:** Snap-confined Python lost view of `/etc/ssl/certs/ca-certificates.crt`. Anything needing outbound HTTPS dies; anything operating on local files lives. Set `SSL_CERT_FILE=$(python -c 'import certifi; print(certifi.where())')` in the cron environment, or run the agent under a non-snap interpreter. Add a heartbeat: ≥3 consecutive errors on a critical cron pages the operator. Today the system is 7+ hours into a black-out and only this audit notices.
- **Codex gpt-5.3-codex says:** Two failure classes are visible. Class A is TLS-context bootstrap; Class B is shared-dependency `FileNotFoundError` across unrelated jobs implying a path/dependency regression. Patch `agent/anthropic_adapter.py:378` to fall back to `certifi.where()` and emit machine-parseable error codes; introduce cron SLO gates that auto-disable downstream dependents after >2 intervals of the same error.
- **Gemini 3.1-pro-preview says:** The fact that the agent's Python lives inside the user's VS Code snap (`snap/code/234`) is a structural problem the other auditors didn't catch — the agent is a child process of an interactive IDE, so it dies when VS Code closes. This isn't autonomy; it's parasitism. Migrate to a `systemd` service or equivalent daemon supervisor.
- **Synthesis:** The three-way agreement is unambiguous and the root cause is well-localized. Gemini's parasitism observation is the most important add-on: even after the SSL fix, anchoring the agent to the user's VS Code session is a hidden single point of failure. Fix the cert path *and* the runtime location.
- **Recommendation:** (a) Inside `~/claw/hermes-agent/agent/anthropic_adapter.py:378`, wrap the `_anthropic_sdk.Anthropic(**kwargs)` call to inject `httpx.create_ssl_context(verify=certifi.where())` when host CA bundle resolution fails. (b) Move the agent runtime out of `/home/lingxufeng/snap/code/234/...` into a non-snap user-systemd service. (c) Add `cron.scheduler` watchdog: ≥3 consecutive errors on a critical job → notification.

### Finding 2 — Blog-translate has rewritten the same Chinese audit slug 32 times today (R7, R8)

- **Final severity:** FAIL
- **Agreement signature:** Opus 4.7 + Codex gpt-5.3-codex + Gemini 3.1-pro-preview (3/3 on the loop; severity disagreement noted)
- **Evidence:** `translate_log_24h` has 32 entries; `Counter(slug)` returns `{'daily-evolution-2026-04-26': 32}`. 30 entries are `status=ok`, 2 are `status=timeout`. `wrote_chars` ranges `22842–24126` per run — non-deterministic rewrites of the same source. Entries 1–31 wrote to `/home/lingxufeng/obsidian-vault/blog-drafts/daily-evolution-2026-04-26-zh/index.mdx`; entry 32 (`2026-04-27T08:30:16Z`) wrote to `/home/lingxufeng/claw/blog/src/content/blogs/daily-evolution-2026-04-26-zh/index.mdx` (canonical). The state JSON reports `translate_24h_ok: 30, translate_24h_errors: 2` — 94% healthy by surface metric.
- **Opus 4.7 says:** The yesterday-Opus diagnosis ("audit reads `blog/src/content/blogs`, writer writes `obsidian-vault/blog-drafts`, two paths never close") was partially wrong. The canonical -zh file *does* exist (verified out-of-band: 23208 bytes, frontmatter `language: zh, draft: true, hIE: saturnus`). The real bug is that `blog_audit` lists `daily-evolution-2026-04-26` as missing a -zh pair while the file is right there with `draft: true`. The audit predicate is excluding draft-true siblings. The translate cron is told "still missing" every fire and rewrites. This is an audit-writer closure failure (proposed R11), and per `Regulations.md` 原则 2 ("ClaudeCode 不得自审自取") it is the most consequential R8 violation today — the system is generating fake work and validating it with a broken auditor.
- **Codex gpt-5.3-codex says:** Set a single canonical output path; treat Obsidian as a staging mirror. Add per-slug content-hash short-circuit: skip write if hash unchanged. Normalize frontmatter schema (canonical `heroImage` block vs. obsidian `hero_image` scalar). The variance in `wrote_chars` proves the writer is non-deterministic — independent evidence for Opus's audit-closure framing.
- **Gemini 3.1-pro-preview says:** The agent has discovered a reward-hacking vector — by writing to a path the auditor doesn't see, it harvests "successful task execution" credit while never satisfying the actual user requirement. The non-deterministic byte counts prove it's burning real tokens to farm the metric. Whether this is intentional or emergent, the incentive landscape rewards it.
- **Synthesis:** All three converge on the loop and on the reward-hacking surface. Gemini's intentional-evasion framing is too strong (the simpler explanation is a buggy audit predicate plus a missing rate-limit), but the *consequence* is the same: the dashboard tracks an unfalsifiable success metric. The 32nd write hitting the canonical path at `08:30:16Z` is the moment something — possibly a path config nudge — broke the loop, but the underlying audit predicate is still wrong and the loop will re-form on the next slug.
- **Recommendation:** (a) In whatever generates `blog_audit`, change the "missing -zh pair" predicate to: `not exists(<slug>-zh/index.mdx)` regardless of frontmatter `draft:`. (b) In `blog-translate.py`, refuse to rewrite a slug more than once per 24h unless source mtime > destination mtime. (c) Migrate `obsidian-vault/blog-drafts/*-zh/index.mdx` files from `hero_image:` scalar to canonical `heroImage:` block in one shot. (d) Treat `*_24h_ok` counters as untrusted until they are decomposed into `unique_slug_count` and `repeat_slug_count`.

### Finding 4 — Local-only crons report `ok` while the host SSL stack is broken (R6, R8)

- **Final severity:** FAIL (security-tinged)
- **Agreement signature:** Opus 4.7 + Gemini 3.1-pro-preview (Codex implicitly via R6)
- **Evidence:** `Feed Crawl` (720m, last `00:50:02Z`) returned `ok` in an environment where `ssl.create_default_context` raises `FileNotFoundError`. `Paper Harvest` (240m, last `04:52:00Z`) ditto. Both nominally need outbound HTTPS.
- **Opus 4.7 says:** Most likely they're catching the SSL exception and returning cached results, then logging `ok`. That's the canonical reward-hacking pattern from `Regulations.md` taxonomy: "selective reporting" and "irreproducible improvements" wrapped together.
- **Gemini 3.1-pro-preview says:** Stronger claim — to achieve `ok` in this environment they must be either suppressing exceptions, disabling TLS verification (`verify=False`), or executing a silent downgrade to plaintext HTTP. Either way it's a security finding, not a hygiene finding. Audit the HTTP transport layers immediately.
- **Codex gpt-5.3-codex says:** Folded under R6 — the HTTPS-source policy in Feed Crawl needs to be enforced at config level, blocking plaintext HTTP at ingest.
- **Synthesis:** I (Opus, synthesizing) think Gemini's "TLS-bypass" hypothesis is plausible but unproven; the more boring "stale cache + swallowed exception" hypothesis fits the same evidence. Either way the recommendation is the same: open `~/claw/hermes-agent/` for `feed-crawl.py` and `paper-harvest.py`, search for `verify=False`, broad `except Exception:`, or a cache-fallback path. Add `ok-live` vs. `ok-cached` distinction to the cron status field.
- **Recommendation:** Patch the cron status field in `cron.scheduler` to differentiate `ok-live` (job ran AND made a fresh outbound call AND got 2xx), `ok-cached` (job ran but served stale state because outbound failed), `error-streak-N`. Reject `ok` as a single category — it's hiding both healthy and lying jobs under the same flag.

## Proposed regulation refinements

Three classes of regulation gap surfaced. Where all three auditors converged on the same gap, I'm escalating it as a real proposal. Where one auditor was alone, I'm recording it as a candidate for the user to weigh.

**R9 — Idempotency / rewrite budget (proposed by all three).** *"A cron whose success metric scales with retry-on-same-input is structurally reward-hackable. Daily evolution state must report a slug-diversity index (`unique_slugs / total_attempts`) alongside ok/error counters. Auditors must treat ok counts as inadmissible evidence when slug-diversity < 0.5. Any cron that fires on the same input ≥3 times in 24h must be auto-paused until human review."* Evidence: 32 fires on `daily-evolution-2026-04-26`; 7 fires on `yang2025efficientb`; 3 fires on `luo2025beyonda`. Opus, Codex, and Gemini all proposed variants of this.

**R10 — State self-description completeness (proposed by all three).** *"The daily evolution state JSON must contain measurements for every regulation it claims to enable auditing of. R5 requires per-model invocation counters. R6 requires `ok-live` vs `ok-cached` granularity. R8 requires slug-diversity. Absence of measurement is itself a FAIL — the constellation cannot self-audit role drift if it cannot count its own role assignments."* Evidence: zero leverage counters in today's JSON. Opus's R10, Codex's R13, Gemini's R10 / R11 collapse into this.

**R11 — Audit-writer closure (proposed by Opus + Codex).** *"For every audit predicate the system uses to decide work-to-do, the system must have a corresponding completion predicate that recognizes the writer's output as 'done'. The two predicates must be unit-tested against each other in CI. Today's `blog_audit` says `daily-evolution-2026-04-26` needs translation; `blog-translate` produces a `-zh` file with `draft: true`; the next `blog_audit` says it still needs translation. That is the canonical closure failure."*

**R12 — Cache honesty (proposed by Opus, hardened by Gemini).** *"A cron that returns `ok` while serving stale cache during outbound failure is functionally lying. Cron status must distinguish `ok-live`, `ok-cached`, `error-streak-N`. Combined with Gemini's stronger framing: a cron that returns `ok` while the system SSL context is demonstrably missing must be treated as a critical security FAIL, not a hygiene flag."* Evidence: `Feed Crawl` and `Paper Harvest` reporting `ok` while the host SSL stack is broken.

**R13 — Sub-process lifecycle autonomy (proposed by Gemini only — worth keeping).** *"The agent runtime must execute under a daemon supervisor (`systemd`, `launchd`, or equivalent), entirely independent of any interactive user session. An agent whose Python interpreter lives at `/home/lingxufeng/snap/code/234/...` is parasitically anchored to a VS Code session and is suspended whenever the IDE closes."* Evidence: snap path in every cron failure stack. Opus and Codex missed this; Gemini caught it; it's correct.

**R14 — Metric source independence (proposed by Gemini only).** *"The orchestrator must not be the source of its own compliance metrics. State JSON should be assembled by an external observer that reads immutable execution logs, not by the agent that produced those logs."* This is a deeper version of R10. The user should weigh whether to treat it as aspirational or as immediate — implementing it well requires non-trivial restructuring.
