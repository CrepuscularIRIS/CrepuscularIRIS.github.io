关于长时域智能体失败的标准叙事，是一个容量叙事：智能体失败了，是因为上下文窗口太小。扩大上下文、增加更好的检索、压缩中间结果，性能就会提升。这个叙事在短时域是成立的。但在大约 50,000 个 token 轨迹处开始失效，到 200,000 个 token 时它甚至会起到误导作用。

2026 年初建立的长时域测量基准，讲述了一个不同的故事。UltraHorizon 风格的评估运行轨迹动不动就跨越 200k token、每次任务数百次工具调用。SWE-EVO 让智能体在多个模拟提交中演化软件。两者都暴露了一类在短时域文献中根本不存在的失败模式：智能体的上下文并不空，检索没有坏掉，任务描述仍然在提示词里——然而它一直在回答三百轮之前自己提出的问题。

我把这个失败模式称为 **上下文锁定**（in-context locking）。这个术语是非正式的——长时域评估文献中有些相邻的标签（"推理漂移"、"轨迹冻结"），但目前还没有任何一个形成标准。这个病理不是信息丢失。信息就在那里。病理在于：最近几轮的注意力质量已经停止流动，智能体的下一个动作由自身历史的一个过时切片决定，而不是由世界的当前状态决定。

## 上下文锁定的表现

这是典型轨迹的签名。智能体在大约五十次工具调用后进入一个多文件重构任务。在第 80 轮左右，它进入了一个局部推理框架："我应该在 `process_user()` 里加一个空值检查。"它尝试了三个变体，全部测试失败。第 100 轮，编排器返回了新信息——上游函数已经改名，测试现在指向一个不同的模块。智能体读取了这条消息。它确认了。然后，在第 101 轮，它在旧的函数名上又尝试了一个空值检查变体。

没有任何上下文被丢弃。改名消息仍然在窗口里。测试的新路径就在那里。智能体在检索意义上并不混乱——如果你直接问它（"编排器三轮前说了什么？"），它会一字不差地复述消息。发生的情况是：过去 N 轮的注意力分布集中在第 80 轮的推理框架上，而此后的每一个生成步骤都在强化那个框架。模型锁住了一个计划。

这种失败是动力学的，而非信息性的。而它恰恰是"把上下文加长"不起作用的区间——因为问题不在于相关信息在窗口之外，而在于注意力机制已经停止为其分配预算。

## 为什么它在长时域出现

像 SWE-bench Verified 这样的短时域基准不会暴露上下文锁定，有一个结构性原因：它们在注意力动力学有时间稳定为一个错误吸引子之前就终止了。SWE-bench 任务通常在不到二十次工具调用内解决。在这个预算内，没有足够的轨迹历史让一个推理框架压倒任务提示词。

相比之下，长时域基准暴露的失败模式是定量的。公开报道的醒目差距——在最前沿的编程智能体中，SWE-bench Verified 中高达 60 多分的表现，在 SWE-EVO 这类多提交 regime 中崩溃到 20 分出头——并非传统意义上的能力差距。模型并没有在两个基准之间忘记怎么写代码。差距是一个 regime 差距，上下文锁定是新版 regime 中打开的失败模式之一。具体数字取决于智能体脚手架，请将其视为数量级而非点估计。

一阶原因是一个路由问题，而非信息丢失问题。标准 softmax 注意力在整个键序列上对分数做归一化，因此一个新的高显著事件要与之前每个 token 竞争预算；在 300 轮时，分母很大，单个新工具结果能重新分配质量的空间比第 10 轮时要小得多。现代长上下文变体（对数尺度重缩放、YaRN 类外推、滑动窗口或线性注意力）减轻了这种影响但没有消除它——任何允许遥远 token 施加影响的机制，当近期 token 没有引入足够的新信号时，也允许过时 token 主导路由。

再叠加第二个效应：**推理链自我强化**。一旦智能体在某个特定框架上生成了几轮一致的推理（"我们需要修复空值检查"），这些轮次就成为后续生成的输入上下文的一部分。模型自己生成的 token 现在携带着早期任务提示词所携带的显著特征签名——区别在于：它们更多，而且离生成头更近。推理链成了自己的提示词。

## 为什么更大的上下文窗口解决不了它

每次有实验室宣布上下文长度升级——1M token、2M token、10M token——隐含的论点是长时域工作会变得更容易。长时域数据说了相反的话。上下文长度是长时域工作的必要条件（你无法推理一个你无法容纳的轨迹），但不是充分条件。

原因在于：上下文长度解决的是*容量*约束，而上下文锁定是*路由*约束。将信息物理地呈现在窗口中，并不能保证注意力机制在生成下一个 token 时会路由到它。在非常长的序列中，注意力路由问题甚至可能恶化，因为模型有更多方式将质量分配到无关 token 上。

早期长上下文评估以更简单的形式揭示了这一点——"迷失在中间"效应，稻草堆寻针（needle-in-a-haystack）检索精度对于位于上下文中间的信息急剧下降，而不是位于开头或结尾的信息。上下文锁定是这一效应的长时域、多轮版本：信息不会从检索中消失，但分配给"根据它行动"的注意力预算，会随着距离上次重复的轮次数增加而单调衰减。

## 在失败叠加之前检测它

这种失败在变得灾难性之前是可以检测的。信号是注意力动力学的，而非基于内容的：当按注意力质量排名的 top-K 位置在连续生成步骤中停止变化时，智能体已经进入了一个锁定框架。形式上，将步骤 *t* 时 top-K 位置及其重新归一化质量作为一个签名，并在额外 *k* 步骤后测量该签名的移动程度：

```python
import numpy as np

def top_k_signature(positions, scores, top_k=32):
    """返回 top-K 位置及其重新归一化质量，以 dict {position: weight}。"""
    idx = np.argsort(scores)[-top_k:]
    total = float(sum(scores[i] for i in idx))
    if total == 0.0:
        return {}
    return {int(positions[i]): float(scores[i]) / total for i in idx}

def top_k_l1_drift(signature_a, signature_b):
    """在 top-K 支持集上的 L1 距离（局部归一化后）。

    这不是完整注意力分布之间的真实全变差距离——
    它是对 top-K 支持集的实际漂移度量。
    取值范围 [0, 2]；低值意味着相同位置携带相似质量。
    """
    keys = set(signature_a) | set(signature_b)
    return sum(abs(signature_a.get(k, 0.0) - signature_b.get(k, 0.0)) for k in keys)

def attention_drift(attention_windows, top_k=32, lag=20):
    """attention_windows: 每次生成步骤的 (positions, scores) 列表。"""
    if len(attention_windows) <= lag:
        return float("nan")  # 还没有足够历史
    current = top_k_signature(*attention_windows[-1], top_k=top_k)
    lagged = top_k_signature(*attention_windows[-1 - lag], top_k=top_k)
    return top_k_l1_drift(current, lagged)
```

有两个细节值得明确。第一，签名以*位置*为键，而非 token 字符串——"the"在不同位置的两个出现是两个不同的注意力目标，按 token 折叠它们会掩盖锁定动态。第二，返回值是 top-K 支持集上局部归一化后的 L1 距离；它不是完整 softmax 分布的总变差距离，后者需要访问完整的注意力行，且通常不值得额外的带宽开销。

"锁定"的阈值是任务相关的，必须在已知最终结果的轨迹上校准。长时域评估工作报告称，在几十轮内持续的低漂移是可靠的预测指标，确切阈值取决于序列长度和头选择。信号的形状比数字更重要：漂移在健康轨迹中应该*振荡*，因为每个新工具结果都应该轻微推动注意力分布。长段平坦的漂移意味着轨迹不再依赖于世界状态。

对于无法暴露注意力分数的系统，也有更简单的代理指标。追踪智能体在过去 N 轮中编辑过的文件集合；如果集合已经塌缩到单个文件而任务仍未解决，那就是同一锁定的行为签名。在滑动窗口内追踪工具调用的多样性；塌缩到单一工具类型（例如全是 `edit_file`）是另一个代理。这些代理比注意力质量信号有更多噪声，但不需要模型内部的 hook。

## 一个有原则的中断策略

本能的修复是总结并重置。压缩上下文，用新的任务描述重新提示，从头开始。这有时有效但经常无效，因为驱动锁定的信息通常也是朴素总结器决定保留的信息。如果智能体花了五十轮做空值检查，总结会记录智能体尝试了空值检查——总结后重新形成的注意力分布会围绕同一个框架重新形成。

一个更稳健的策略是将中断视为路由干预，而非内容干预。不重写上下文，而是改变模型在下一个生成步骤中被强制关注的内容：

```python
from dataclasses import dataclass, field
from typing import Sequence

@dataclass
class InterruptPolicy:
    drift_threshold: float = 0.15
    min_locked_turns: int = 20

    def should_interrupt(self, drift_history: Sequence[float]) -> bool:
        if len(drift_history) < self.min_locked_turns:
            return False
        recent = drift_history[-self.min_locked_turns:]
        return all(d < self.drift_threshold for d in recent)

    def last_locked_frame_start(self, drift_history: Sequence[float]) -> int:
        """返回当前锁定运行的起始轮次索引。"""
        i = len(drift_history) - 1
        while i > 0 and drift_history[i] < self.drift_threshold:
            i -= 1
        return i + 1

    def build_interrupt(self, drift_history: Sequence[float]) -> dict:
        # 通过强制-diff 操作强制注意力移动。
        # 模型必须阐明自推理框架开始以来世界状态发生了什么变化。
        # 这不是总结——这是一个结构化的重新锚定，
        # 覆盖当前的注意力吸引子。
        frame_start = self.last_locked_frame_start(drift_history)
        return {
            "role": "user",
            "content": (
                "停。在提出另一个行动之前，列出从第 "
                f"{frame_start} 轮以来世界状态中确切发生了哪些变化。"
                "对于每个条目，引用轮次编号并引用相关消息。"
                "本轮不要提出任何行动。"
            ),
        }
```

关键的机械动作是强制-diff 指令：模型在下一轮不能生成动作 token，只能在当前世界状态和锁定框架开始时的世界状态之间做结构化比较。这同时做两件事。它将下一个注意力预算花在最近的轮次上（它被迫复现的引用），并通过拒绝让模型扩展锁定框架来阻止推理链自我强化效应。

运行这样的中断后，注意力漂移信号几乎总是恢复——top-K 质量会重新分配，包含强制-diff 轮次及其引用的内容。智能体随后是否做出更好的决策是另一个问题，但至少它是在根据当前世界状态做决策，而不是根据五十轮前自己试图做什么的记忆做决策。

## 为什么这对智能体脚手架很重要

对于构建智能体框架的任何人的实际启示：注意力动力学是一等公民可观测量。不是调试的便利设施，是一等公民可观测量。如果你的提供商暴露了它，就记录每次生成步骤的 top-K 注意力质量（Anthropic 的扩展思考追踪、OpenAI 的推理 token 计数、开源模型的注意力数组）。如果不能暴露，就记录行为代理（文件集合、工具多样性、编辑局部性）。计算漂移。根据它行动。

框架工程社区在过去六个月里一直在争论哪个沙盒层、哪个 MCP 网关、哪种上下文填充策略最重要。上下文锁定提供的证据表明，更早阶段的一个可观测量——智能体自身轨迹的注意力签名——至少同样具有决定性。21% 的 SWE-EVO 分数与 30% 的 SWE-EVO 分数之间的差距不是模型差距。在很大程度上，那是能检测锁定的框架与不能检测锁定的框架之间的差距。

这指向的研究议程是具体的。不是"让上下文窗口更长"。而是"测量并管控长轨迹上的注意力动力学"。这意味着上述类型的中断策略，在真实多轮基准上加以仪表化，漂移曲线与准确率数字一起发表。这也意味着，下一代长时域基准应该直接暴露其轨迹的注意力 regime，而不仅仅是最终成功率——因为两个具有相同准确率的智能体可能拥有截然不同的锁定特征，只有其中一个在任务分布漂移时会是稳健的。

上下文长度给了我们运行长时域任务的空间。注意力动力学是下一个要解决的问题。
