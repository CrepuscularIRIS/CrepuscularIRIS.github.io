# 一句话摘要

**约 100 条标注样本是专用小模型追平通用大模型文本分类性能的盈亏平衡点。** Pecher 等人将这一经验阈值转化为可复现的基准协议，为成本敏感场景下的模型选型提供了具体决策依据。

---

# 为什么值得读

多数团队做文本分类时默认调用 GPT-4 级别的模型，因为 API 只需要一行代码。隐性成本在推理端：每条预测都在消耗 token，规模放大后账单惊人。微调一个 1 亿参数的专用分类器，单次推理成本极低，但前提是手里已有标注数据。这篇论文问了一个大多数人跳过的问题：**你到底需要多少标注样本，小模型才开始划算？**

对 ACCEPTA "boundary_accuracy" 研究议程而言，这是上游基础设施。如果我们希望认知基准能够清晰映射到真实世界的成本曲线，就需要有论文量化"标注投入"与"推理投入"的交叉点。Pecher 等人提供了方法论。

---

# 核心方法（3 分钟版）

作者设计了一场受控赛马。一侧是通用大模型（推测为 GPT-3.5/4 级别），以 zero-shot 或 few-shot 方式完成标准文本分类任务；另一侧是小型专用模型（BERT 量级或轻量编码-解码器），在逐步增加的标注数据上进行微调。

自变量是**标注样本数量**。因变量是**分类准确率**（或 F1，视任务而定）。论文追踪小模型的学习曲线，直到它与 LLM 的 zero/few-shot 性能水平线相交——这个交点就是盈亏平衡点。

让结果可信的关键设计：

- **多数据集、多任务类型** —— 不是单一精心挑选的基准。
- **成本框架** —— 作者 reportedly 将样本数量转化为标注成本和推理成本，让工程团队能直接看到权衡。
- **可复现协议** —— 细节足够充分，其他团队可以在新模型上重跑整条曲线。

核心直觉：大模型是数据高效的 learner，但是昂贵的 machine；小模型是廉价的 machine，但是数据 hungry 的 learner。这篇论文画出了两条曲线的交汇点。

---

# 关键结果

- **约 100 条标注样本** 是跨任务的近似盈亏平衡阈值。低于此数量，LLM 更优；高于此数量，微调后的小模型成为成本-准确率最优解。
- **成本曲线因任务而异。** 细粒度情感分析、多标签分类等任务会推高盈亏平衡点；粗粒度二分类任务则降低它。
- **来源中无具体数字** —— 提取材料中缺少准确的准确率差异、方差估计或逐任务盈亏平衡数据。"100 条样本"来自论文标题，在完整审读前应视为数量级层面的主张。

---

# 局限与未解问题

- **来源中无具体数字。** 提取摘要缺少实际的准确率表格、方差估计或逐任务盈亏平衡点。"100 条样本"的标题是一个值得关注的信号，但尚未经过验证。
- **对比的是哪个大模型？** 标题和摘要未明确说明对比对象是否为 API 模型（GPT-3.5/4）、开源权重模型（Llama-2/3）或两者皆有。模型代际会显著改变盈亏平衡点。
- **推理成本假设** 依赖于云厂商定价、批次大小和延迟要求。2024 年 AWS us-east-1 的结论，未必适用于 2026 年的本地边缘部署。
- **静态基准，动态目标。** 新型小模型（ModernBERT、DeBERTa-v3）和新提示技术（思维链分类、自一致性投票）可能在不改变论文协议的情况下，就已经移动了交叉点。
- **ACCEPTA 关联是推测性的。** 论文本身并未提及 ACCEPTA 或认知基准测试；"boundary_accuracy" 的相关性是策展推断，而非作者主张。

- **Hoffmann et al. (2022, Chinchilla)** —— 将争论焦点从"模型大小"转向"训练 token 量"，间接影响了小模型追赶所需标注数据的数量。
- **ACCEPTA Executive Functions benchmark** —— 若你正在构建成本感知的认知评测，本文的协议可作为"每美元准确率"子指标的模板。
