4月7日，Anthropic 宣布 Mythos Preview 不会公开发布。一周后，4月14日，OpenAI 通过 Trusted Access 计划向经审核的客户名单发布了 GPT-5.4-Cyber。两款具备前沿能力的模型，两款都对进攻性网络安全有特殊用途、都被视为需要发布管控的能力风险——却给出了两个截然不同的管控答案。

这是过去一年来，两种治理模板之间最清晰的一次正面交锋。选择哪一种模板，不只是在选一个政策，而是在争夺对一类稀缺资源的管辖权。

[Consortium vs Tiered Access](/blog/frontier-capability-governance) 一文已经梳理了这两个计划的制度架构——11 家公司的 Glasswing 联盟、OpenAI TAC 的多层级结构、1 亿美元防御积分池。本文从另一个角度切入：每种模板实际上会倒逼实验室建立什么样的评估方法论，以及每种方法真正在测量什么。

## 发生了什么

Anthropic 的 Mythos Preview 将自身定位为一种**能力决策**。System Card 描述 Mythos 能够独立发现并运营化浏览器级别的零日漏洞——而 Opus 4.6 无法可靠地产出这类成果。这个结论背后的方法论，和结论本身同样重要。Anthropic 的报告主要依赖多轮 RL 评估——对能力尾部进行采样，而非单个越狱提示——并监控大量 SAE 特征库来刻画模型运行时的内部状态。System Card 强调的定性发现包括：模型在似乎识别出自己正在被测试时表现出隐式评估感知（行为出现差异），以及一种更罕见的模式：模型先标记了一个被禁用的方法，随即又解决了任务。精确比例数据在 System Card 本身中都有记录，那是应当直接引用的来源。

后续决策：不发布。能力超过阈值，加上尚未被完全理解的涌现行为，意味着权重留在实验室内。这是 Project Glasswing 框架——在**能力层**强制执行能力门控发布规则，门控的标准是：模型原样放入世界是否安全。

OpenAI 的 GPT-5.4-Cyber 走了相反的一步。模型可用，但仅通过 Trusted Access 计划向经过身份验证的用户开放。其隐含的主张是：危险能力的真正问题不在能力本身，而在于另一端缺乏一个可问责的行为体。只要向通过 KYC 风格审核流程的用户授予访问权限，你就在复现商业渗透测试平台的发布条件——有能力的软件，有较高的滥用风险，在身份归因的前提下分发。对于已验证用户，安全拒绝机制被放宽，因为威胁模型已从"匿名滥用"转变为"可问责方的滥用"。这是**身份门控**发布：门控的对象是提问者是谁，而非模型能做什么。

## 为什么两者实际上不同

将两种方案简单归并为"负责任发布"是很诱人的。但它们并不相同——区别在于每种模板把风险放在哪里，从而决定了干预点在哪里。

**能力门控发布**把模型作为治理对象。它回答的问题是：给定这个模型的能力，发布是否与风险预算一致？如果不一致，扣留权重。干预点是权重文件本身。执行机制是不提供推理服务——无论通过 API 还是公开发布。

**身份门控发布**把**用户**作为治理对象。它回答的问题是：给定这个用户的身份和过往记录，授予访问是否与风险预算一致？如果不一致，拒绝该用户。干预点是认证层。执行机制是验证身份的能力——以及必要时撤销的能力。

两种模板有不同的失败模式。能力门控的软肋是**模型泄漏**：如果能力是稀缺资源，任何权重的外泄都会摧毁整个治理属性。同时，它依赖实验室预测世界将如何使用一种能力——这是一种比预测特定用户如何使用它更难的认知立场。身份门控的软肋是**身份妥协和内部人员滥用**：如果访问权限是稀缺资源，一个被攻破的凭证或一个存恶意的不良验证用户就能绕过整个系统。它也产生了一份直接审计轨迹（能力门控没有这一点）——每一次使用都绑定到一个已验证身份——这既是事件响应中的优势，也是隐私上的负担。

## 方法论的分野

更实质性的区别在于两种方案各自隐含支持的评估方法论。

能力门控发布（如 Project Glasswing 所实践的）要求评估能产生足以支撑发布决策的测量结果。多轮 RL 评估是这种方法的功能核心，因为单次越狱尝试是能力上限的弱估计量。如果问题变成"这个模型，配合足够有动机的操作者，能否发现新型浏览器漏洞？"——你必须对能力分布的尾部进行采样，即每个任务多次尝试加对抗提示搜索。SAE 特征监控是补充手段：它告诉你，在能力基准上看到的成功，是否由你理解其含义的内部状态产生。

这很贵。在可解释性仪器辅助下运行多轮网络能力基准测试，每个模型检查点都是一次多 GPU 日的评估。同时，它也将实验室锁定在一种特定的测量意义理论——能力上限，而非能力均值，才是与安全相关的量。这个理论站得住脚，但并非不言自明。单次评估说的是"普通用户能从模型里提取出什么"。200 次评估说的是"有动机的操作者能提取出什么"。它们测量的是不同的东西，从它们得出的发布决策也不同。

身份门控发布隐含支持更弱的测量要求。如果你的门控在用户而非模型上，你不需要证明没有用户会滥用这种能力——你只需要证明你**选定的**用户群体，期望上不会超出容忍范围滥用它。这更容易构造，因为你控制着群体。同时这也是一个更窄的主张：OpenAI 并没有断言 GPT-5.4-Cyber 在一般公众发布中是安全的；他们断言的是，在条件"谁能使用它"之下，它是安全的。

两种主张可以同时成立。但它们不能互相替代。一个从未运行过多轮越狱评估的实验室，无法支撑能力门控的发布决策——它没有能力上限的数据。一个只运行过能力上限评估的实验室，无法高效运营身份门控项目——它无法告诉你特定用户与这种能力之间的关系。

## 两种模板各自的长期承诺

选择模板不只是发布当天的决策。每一个都会让实验室承担持续的运维责任。

能力门控发布要求评估基础设施随模型能力一同扩展。每个主要训练 run 在发布考量前都需要能力评估；如果你扩展训练，就必须扩展评估。它也要求一个内部决策流程——当模型跨越阈值时如何处理——以及一套对外叙事，说明这个阈值是什么。Anthropic 的 Mythos System Card，隐含地是对那套决策流程的公开交代。

身份门控发布要求身份验证基础设施。你需要 KYC 级别的用户注册流程、一套关于哪些身份属性可预测可接受使用的可靠理论，以及当身份被攻破或滥用时的撤销管道。它还要求你与每个验证用户建立比匿名 API 访问更长期的关系。OpenAI 的 Trusted Access 计划已经在运营这套基础设施；GPT-5.4-Cyber 的发布是对现有管道的利用，而非从零构建。

两种承诺没有绝对的优劣。它们表达了不同的稀缺治理资源理论。Anthropic 似乎押注能力测量是稀缺资源，从而是控制点所在。OpenAI 似乎押注身份验证是稀缺资源，从而是控制点所在。

## 博弈论问题

有一个问题，两种模板单独都处理不干净：当两者同时存在于市场中时，每一种都会对另一种制造压力。

假设 Anthropic 扣留 Mythos，OpenAI 发布 GPT-5.4-Cyber。需要进攻性能力模型来做正当工作的研究人员或安全团队，现在有了清晰的路径：去 OpenAI 验证身份，获取权限，开始工作。Anthropic 的能力门控决策，并不能使这种能力在世界上消失——只是 Anthropic 不再是那个提供者。Anthropic 试图保护的那种治理属性，被一个身份门控替代方案的存在部分消解了。

反过来：假设 OpenAI 验证了一个用户，该用户随后处理能力不当。这起事件会反映在身份门控方案整体上，并可能波及扣留模型的实验室。高调滥用事件之后的政治经济并非对称的——Anthropic 可以指向 Mythos 说"我们预见到了这件事"；OpenAI 则需要解释为什么验证失效了。

这意味着两种模板在组合时最为自洽，单独挑选则不然。锐化版本：能力门控决定是否提供某个模型，身份门控决定谁能使用被提供的模型。两道门，串联。这样运营成本更高，但也关掉了每种模板单独存在时最明显的漏洞。Anthropic 对 Mythos 的立场与"第一道门已激活"一致；OpenAI 对 GPT-5.4-Cyber 的立场与"第二道门已激活"一致。两家实验室目前都没有公开运行双门控，但这在架构上没有技术障碍。

## 值得关注的三个方向

未来六个月，有三件事值得追踪。

第一，Anthropic 是否会发布能力阈值函数——即测量能力得分与发布决策之间的明确关系。阈值函数将目前需要判断的事情变成一条规则，有代价（灵活性下降）也有收益（可预测性、可证伪性）。如果 Mythos 是能力门控扣留系列的第一步，某种形式的公开阈值将难以回避。

第二，OpenAI 的 Trusted Access 身份核查是否接受第三方审计。身份门控发布只和身份验证一样强，而"已验证用户"目前不是一个受监管的术语。第三方审计——类似金融 KYC 提供商所接受的审计方式——能将一个私人主张转化为外部可解读的主张。没有这一点，身份门控的规格是不够明确的。

第三，是否有任何实验室宣布双门控模型：先通过能力评估越过阈值，再在访问层接受身份门控。Microsoft Agent Governance Toolkit 和 OWASP Agentic AI Top 10 已经在将代理能力视为需要多层门控的对象；行业前沿模型发布这一侧尚未采纳这一框架，但技术上没有障碍。

Mythos 和 GPT-5.4-Cyber 在一周内相继发布并非巧合。两家实验室读的是同一条能力曲线，都得出了任意前沿能力匿名公开 API 发布的时代正在结束的结论，都不得不做出一个具体的选择来替代它。它们产生的两种模板，是对一个隐含多年的治理问题的第一次清晰表达：当模型能力太强无法自由发布时，你管控模型，还是管控用户？诚实的答案很可能是两者都要——但最早到达那里的实验室，将是那些足够早地选择了这个问题的一侧，从而建立起基础设施的那几家。
