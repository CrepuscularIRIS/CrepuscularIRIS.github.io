# PageGuide：把 LLM 的回答钉回网页上

**原始标题**：PageGuide: Browser extension to assist users in navigating a webpage and locating information  
**作者**：Nguyen et al. | **arXiv**：2604.23772 | **日期**：2026-04  
**链接**：https://arxiv.org/abs/2604.23772

---

## 一句话摘要

PageGuide 是一个浏览器扩展，它将 LLM 生成的回答锚定到网页的具体 DOM 元素上，用**视觉高亮**告诉用户信息从哪来——而不是让用户对黑箱输出照单全收。

---

## 为什么选这篇

现在的浏览器 Agent 大多像神谕：它读了页面，回答了问题，但你完全不知道它有没有编造一半内容。PageGuide 不追求让 LLM 更准，而是让它的推理过程**可被检查**——这击中了信任问题的根子。

更重要的是，当前 AI 助手的主流交互范式（侧边栏聊天）对高风险任务来说是残缺的。Agent 告诉你某条租房信息"没有宠物限制"，你需要亲眼看到条款原文。PageGuide 的覆盖层模式把验证从一项苦差事变成了一瞥就能完成的事。

---

## 核心方法（3 分钟版）

核心直觉很简单：**别告诉用户页面上写了什么——直接指给他看**。

PageGuide 架起了 LLM 自然语言回答与原始 HTML DOM 之间的桥梁。当你提问（"重置密码该点哪里？"）时，系统不只是生成文字步骤，而是把每一条断言映射到页面上的实际元素并高亮显示。

扩展覆盖了三种交互模式。

**Find（查找）**高亮包含答案证据的具体 DOM 节点。相当于"给 HTML 加引用标注"。

**Guide（引导）**提供分步指令，每一步都视觉锚定到用户接下来要点击的按钮、链接或表单字段。

**Focus（聚焦）**调暗或隐藏无关区域，避免用户在跟随引导时被广告、侧边栏或无关内容分散注意力。

实现上它是一个浏览器扩展，因此能实时访问活动 DOM。这一点很关键：与基于截图的方案不同，PageGuide 可以追踪动态内容、响应 SPA 路由变化，并在页面更新时维持覆盖层。

## 关键结果

本文的可用信息仅限于 arXiv 摘要，且摘要被截断。根据现有摘录：

- **锚定机制**：LLM 回答通过视觉覆盖层（高亮框、箭头或聚焦环）显式链接到 HTML DOM 元素。
- **三模式设计**：扩展支持 Find、Guide 和 Focus，覆盖了从被动验证到主动任务完成的完整光谱。
- **浏览器原生部署**：以扩展形式实现，而非代理或外部工具，能够对实时网页进行低延迟交互。

**提供的来源中未出现任何具体评估指标或用户研究结果。** 该论文目前似乎处于早期预印本阶段。

## 局限与未回答的问题

- **评估缺失**：摘录中没有用户研究数据、任务完成率或信任度指标。覆盖层是否真的减少了错误，还是仅仅增加了视觉噪音，目前尚无定论。
- **依赖 LLM 质量**：锚定的上限取决于 LLM 将自然语言正确映射到 DOM 选择器的能力。一个幻觉出的元素 ID 会产生误导性高亮——可能比没有高亮更糟糕。
- **覆盖范围不明**：摘要未说明 PageGuide 如何处理复杂 SPA、Shadow DOM 或动态注入内容。而这些正是用户最需要帮助的场景。
- **对比不足**：没有与现有浏览器 Agent（如 Adept、Operator 类系统）或更简单的基线（截图 + 边界框预测）进行正面比较。
