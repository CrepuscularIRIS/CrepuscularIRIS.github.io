## 一句话摘要

Ramachandran 等人将 GPT-4o、Gemini 等仅提供 API 的多模态大模型，塞进了传统计算机视觉的评估流水线里——通过把分割掩码、边界框、深度图翻译成文本格式，逼问这些靠下一个 token 训练的模型：你到底能不能"看见"？

## 为什么选这篇

多模态大模型的风口已经到了一个微妙的节点。MMMU、MathVista 这类榜单上 GPT-4o 成绩亮眼，但这些本质上是"用图片包装的语言任务"——模型只需要理解图像中的文字和逻辑就行。

这篇论文做了更让人不舒服的事：把同款模型直接丢进语义分割、单目深度估计、目标检测的 benchmark 里——这些任务的真值（ground truth）是空间性的，不是语言性的。

我的判断是：这篇文章的价值不在于具体数字，而在于**测量框架本身**——它揭示了一个被忽视的问题：当你的模型只有一个 API 端点、没有权重的时候，评估基础设施需要重新设计。

## 核心方法（3 分钟版）

传统 CV 基准测试有一个默认前提：你能直接拿到模型的输出张量。想评估语义分割？模型输出一个逐像素的类别 logit 图，直接和真值掩码比较就行。

多模态大模型不按这个逻辑运行。GPT-4o 接收一张图，返回一段文字。要让它在分割任务上接受评估，你需要一层**翻译接口**——用 prompt 让模型以结构化文本格式输出预测结果（比如 COCO 风格的多边形坐标，或者一段密集描述），再用一个解析器把文本转回可比较的格式。

作者的核心方法论贡献就是这个翻译层。他们在三类任务上做评估：

**分割** — 模型输出像素坐标或区域描述；作者将其解析为二值掩码，以 IoU 与标准数据集比对。

**检测** — 边界框以 `"x_min, y_min, width, height"` 这样的文本字符串表达；解析后用标准 AP 指标打分。

**深度估计** — 单目深度图以文本形式输出（相对深度排序或量化值），重建后再比较。

整个评估框架的设计原则是：尽量减少额外的 prompt 工程 tricks，测试的是模型的原始能力，而不是调 prompt 的本事。

## 关键结果

论文来源材料中无具体数字。这篇论文的首要贡献是方法论层面——建立 benchmark 本身的设计与报告框架。闭源模型与开源模型之间的具体性能对比，有待在全文表格中查阅。

## 局限与未回答的问题

**翻译损耗。** 每一次把视觉输出转成文本再转回来，都会引入噪声。一个模型可能拥有极佳的内部视觉表征，但这些表征并不能被流畅地压缩成文本序列的形式。这种评估方式可能惩罚那些优势不善于用坐标序列表达的模型。

**Prompt 敏感性。** 论文不可避免地面临标准 LLM benchmark 问题：结果是模型能力和 prompt 设计共同决定的函数。没有完整的 prompt 策略消融实验，很难判断"差"结果是真正视觉理解能力不足，还是文本输出格式优化不够。

**任务覆盖面。** 三个任务家族只是一个开始，不能代表全面图景。这套方法论能否扩展到视频、三维点云、医学影像？目前不得而知。

**闭源模型的可复现性。** 论文评测了 GPT-4o ——一个会不声不响更新的模型。这篇论文里的任何结果，等你读到的时候可能已经过时了。
